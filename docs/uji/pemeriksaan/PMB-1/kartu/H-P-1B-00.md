### PMB1-F-095 (K-2) — kendali "sesi terikat perangkat + pencabutan seketika" kosong di jalur nyata

- **Reproduksi:** probe asli hakim H-F-06.2 hari ini **GAGAL** di asersi A; saya telusuri dulu sebelum
  menyimpulkan apa pun: penyiapannya memakai perangkat `hp-atasan` (`de…006`) yang **tidak** punya baris
  `persetujuan_perangkat` untuk Rina, sehingga migrasi 0101 menolak login lebih dulu. Karena itu saya tulis
  probe baru yang memakai `hp-kasir` (`de…003`) yang persetujuannya ADA di `alat/sql/data-uji.sql:161`, lalu
  mengukur inti temuannya. Hasil: cacatnya **utuh**.
- **Koreksi bukti (tidak mengubah putusan):** `sesi_masih_aktif()` sebenarnya **dipanggil** — oleh
  `penyewa_saya()`, `peran_saya()`, `cabang_saya()` di `0058:118-160` — jadi cacatnya bukan "tidak pernah
  dipanggil" melainkan "selalu lolos": satu-satunya masukannya (klaim `session_id`/`perangkat_id` atau header
  `x-perangkat-id`) tidak pernah ada, karena 0 `ikat_sesi_perangkat` di klien, 0 `signInWithPassword`,
  0 `setSession`, 0 pengirim `x-perangkat-id`, 0 `custom_access_token`/`auth.hook` di `supabase/`.
- **Refutasi yang gagal:** (a) header `x-perangkat-id` mungkin dikirim klien → 0; (b) `sesi_perangkat` mungkin
  diisi pemicu/trigger → 0; (c) RLS `force` mungkin menyempitkan → 0.
- **Tingkat:** K-2 tepat. Yang hilang adalah penegakan dua janji baseline (`docs/KEAMANAN.md:23` §4 butir 4
  "semua pemeriksaan perangkat/sesi dilakukan di database pada setiap permintaan"; `docs/KEAMANAN.md:127`
