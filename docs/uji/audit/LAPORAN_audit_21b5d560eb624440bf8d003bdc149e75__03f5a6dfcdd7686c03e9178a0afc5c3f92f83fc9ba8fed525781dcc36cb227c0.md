## 4. Temuan

### [F-01] Alur uang kasir tidak bisa diselesaikan: `hitung_total` tidak pernah dipanggil, `bayar_pesanan` menolak total 0
- **Tingkat:** K-1
- **Artefak:** `aplikasi/src/App.tsx:79-118` (tulis `pesanan`/`pesanan_item` langsung dari klien) · `aplikasi/src/layar/kasir/LayarKasir.tsx:204-213` · bukti peladen `supabase/migrations/0009_pesanan.sql:37`, `supabase/migrations/0048_wajib_shift.sql:280-282`
- **Klaim yang dilanggar:** T1-15/T5-02/T5-03 — "angka yang SAH selalu datang dari peladen (`hitung_total`)" (`LayarKasir.tsx:204`), "uang hanya lewat RPC `bayar_pesanan`", "alur menu → catatan → kirim dapur → bayar tunai lunas lulus".
- **Bukti:** `grep -rn "hitung_total" aplikasi/src --include='*.ts' --include='*.tsx' | grep -v '\.test\.'` → hanya komentar, `lib/aksi.ts` (registri), `lib/tarif.ts`, dan `src/uji/harness` — **nol pemanggilan runtime**. Lalu `grep -n "total" supabase/migrations/0009_pesanan.sql` → `total integer not null default 0`; `sed -n '280,282p' supabase/migrations/0048_wajib_shift.sql` → `if coalesce(v_pesanan.total,0) <= 0 then raise exception 'Total pesanan belum dihitung — pembayaran belum boleh dicatat.';`.
- **Skenario gagal:** kasir menambah menu → "Kirim ke Dapur" (menulis `pesanan` + `pesanan_item`, kolom `subtotal` dihitung di klien, `total` tetap 0) → "Proses Bayar" → `rpc('bayar_pesanan', {p_pesanan_id: pesananAktifId})` (`aplikasi/src/hook/useBayar.ts:172-179`) → peladen menolak "Total pesanan belum dihitung". Bila pesanan belum pernah disimpan, App mengirim id literal `'ord-current'` (`App.tsx:56,62`) ke parameter `uuid` → galat tipe. **Akibat: transaksi tidak dapat dilunasi di sistem nyata; uang tidak tercatat.**
- **Dugaan penyebab:** kontainer App (`onSimpanPesanan`) ditulis sebagai jembatan sementara sebelum RPC `simpan_pesanan`/`hitung_total` (yang masih berstatus "belum ada" di paket §1b) selesai; uji E2E memasang mock sendiri sehingga celah ini tidak pernah merah.
- **Cara membuktikan perbaikan:** tambahkan uji integrasi App yang setelah `onSimpanPesanan` **wajib** mengamati panggilan `hitung_total` (mis. `grep -n "hitung_total" aplikasi/src/App.tsx` tidak kosong DAN `cd aplikasi && npm test -- src/App.test.tsx` hijau dengan asersi urutan), plus uji SQL/RPC yang menolak pesanan tanpa total — lalu buktikan suite MURAH: `node aplikasi/alat/uji-mutasi-app.mjs` memuat mutasi "hapus panggilan hitung_total" yang wajib MERAH.
- **Status verifikasi:** TERVERIFIKASI (kode + skema SQL dibaca langsung; bukan dijalankan karena sandbox tanpa `node_modules`, lihat §6)

### [F-02] Tombol "Kirim ke Dapur" selalu melaporkan sukses palsu
- **Tingkat:** K-2
- **Artefak:** `aplikasi/src/layar/kasir/LayarKasir.tsx:138,340-372` · `aplikasi/src/App.tsx` (tidak meneruskan prop)
- **Klaim yang dilanggar:** SPESIFIKASI_UI §9.3.3 ("tidak boleh 'fungsi ada tapi tak bisa dipakai'"), §9.3.5 ("kegagalan tidak boleh berupa 'tidak terjadi apa-apa'"), registri aksi `kasir.kirim_dapur` (RPC `hitung_total`).
